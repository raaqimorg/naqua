How the Naqwa purification API works

A guided tour of naqua-api: what each file is for, how the server starts, and what happens to an HTTP request from the moment Node accepts it to the moment the JSON leaves. File references point at the working tree as of 3 October 2026.

01Overview

A small, read-mostly HTTP API that serves Shariah purification rates for Saudi (Tadawul) stocks, and calculates how much a holder needs to purify. It runs the same arithmetic as the calculator on trynaqua.com, and a test sweep checks that the two produce the same numbers.

03Boot sequence

The program is a single Layer. Effect builds each layer before the layers it is provided to, so the order of construction is fixed and visible in src/server.ts.

// src/server.ts:11
const ServerLayer = HttpRouter.serve(AppLayer).pipe(
  Layer.provide(NodeHttpServer.layerConfig(createServer, { port: PORT })),
  Layer.provide(Dataset.layer),
);

NodeRuntime.runMain(Layer.launch(ServerLayer));
The data file is validated before the port opens. A malformed companies.json crashes the boot, Render's health check never passes, and the previous deploy keeps serving.

What each step builds

  1. Dataset. loadDataset() reads data/companies.json and runs decodeDataset, which checks the field schema and the rules across records and lists every problem in one error. parseDataset then adds version (the first 12 hex characters of the file's SHA-256), the list of years, and a lookup(ticker) backed by two Maps. src/data/dataset.ts:28
  2. HTTP server. NodeHttpServer.layerConfig reads PORT through Effect Config, with 3000 as the default. src/config.ts:10
  3. API middleware. RateLimit.layer reads Clock and REQUESTS_PER_MINUTE once when it is built, which is how tests inject a fake clock and a small limit, and keeps a Map<client, {count, resetAt}> in the order the windows opened, capped at 10,000 clients. DataVersion.layer reads the dataset's version. src/http/middleware.ts · src/http/rateLimit.ts
  4. The app. AppLayer is a Layer.unwrap because the API definition depends on runtime values: the calculation schema states the data's real coverage dates, and the OpenAPI description states the rate limit and server URL. It merges the generated API (with /openapi.json, its four handler groups and the layers of its four middleware), the Scalar docs at /docs, the index route, and the router middleware. src/app.ts
  5. Serve. HttpRouter.serve attaches the router to the server, with Effect's default matching: case does not matter and a trailing slash is ignored. Any spelling that reaches an endpoint still runs that endpoint's middleware, rate limit included. src/server.ts
  6. Run. NodeRuntime.runMain(Layer.launch(...)) keeps the process alive and turns the SIGTERM Render sends on deploys and spin-downs into an orderly shutdown. src/server.ts:17
Handlers do their per-boot work once. Each handler group runs its setup a single time, when the layer is built. companiesHandlers sorts and summarises the whole company list once, and metaHandlers builds the meta object once. A request to either only returns a value that already exists. This is safe because the data changes only with a deploy.

The same app, without a server

makeTestApp (test/helpers.ts) provides AppLayer with a given dataset, a ConfigProvider holding the test's rate limit, an optional test Clock and HttpServer.layerServices, then turns it into a (Request) => Promise<Response> using HttpRouter.toWebHandler, with logging turned off. Every test drives the app this way, so the tests run the same middleware and handlers as production without opening a port.

04The request pipeline

Two kinds of middleware. The router's, RouterMiddleware, wraps every request and handles what no endpoint sees: CORS, the security headers, an unknown route and a defect. Everything else is API middleware that the endpoints declare in api.ts, so it runs only for them, and the errors it raises are in the OpenAPI document. Pick a scenario to trace its path through the stages.

  1. 1
    Request arrives
    node:http → NodeHttpServer → HttpRouter
    The router middleware wraps everything after this point, the router and every route.
  2. 2
    Is it OPTIONS?
    middleware.ts · HttpMiddleware.cors
    Effect's CORS middleware answers every OPTIONS request as a preflight with 204, before routing. It allows GET, POST and Content-Type, with a max age of 86400. Any other response gets Access-Control-Allow-Origin: * and the exposed headers.
  3. 3
    Route matching
    HttpRouter
    Effect's default matching: case does not matter and a trailing slash is ignored. If no route matches, including a wrong method, the router fails with RouteNotFound, and the router middleware answers 404 NOT_FOUND. No endpoint ran, so no quota is used and there are no data headers.
  4. 4
    Data version
    middleware.ts · DataVersion
    The outermost middleware of every /v1 endpoint. It attaches X-Data-Version to whatever response the request ends with, a typed error included.
  5. 5
    Rate limit
    middleware.ts · RateLimit · rateLimit.ts
    Counts the request against the client's one-minute window. The client key is the first X-Forwarded-For address if it is a real IP address, otherwise the socket address. It attaches the RateLimit-* headers, and past the limit it fails with RateLimited: 429 with Retry-After. /health is added to the API after this middleware, so it is never counted.
  6. 6
    Body checks
    middleware.ts · JsonBody (calculate only)
    A declared Content-Length over 100 KB is refused unread with 413. Without the header (a chunked upload), the body is read with a 100 KB cap, and the payload decoder reuses that read. Then the body must be Content-Type: application/json, or the answer is 400 VALIDATION_ERROR.
  7. 7
    Schema decoding
    HttpApiBuilder · schemas.ts · RequestValidation
    Path parameters (strings) are decoded to integers, and the payload is parsed and decoded with errors: 'all'. A failure is an HttpApiSchemaError, which RequestValidation turns into 400 VALIDATION_ERROR with details: [{path, message}], or into the "could not be parsed" message if the body was not JSON. Only the three endpoints that take input declare it, so only they document a 400.
  8. 8
    Handler
    handlers/*.ts · errors.ts
    The handler receives typed params or payload. It resolves the ticker and looks up rates. A business failure is yield*-ed as a Schema.Error (UnknownTicker, AmbiguousTicker or RateNotAvailable), and the API encodes it with the status the class declares.
  9. 9
    Unexpected failure
    middleware.ts · RouterMiddleware
    Any other defect, such as an exception thrown inside a handler or a response that fails its own schema, is logged with Effect.logError and answered with 500 INTERNAL_ERROR. Nothing internal reaches the client.
  10. 10
    Success encoding
    api.ts · schemas.ts
    The handler's value is encoded with the endpoint's success schema into a 200 JSON response. On a GET (and so a HEAD), DataVersion adds Cache-Control: public, max-age=3600.
  11. 11
    Decorate the response
    RouterMiddleware · response handlers
    The router middleware adds the security headers. As the response is sent, the headers the middleware attached along the way are applied: CORS, and for a /v1 endpoint RateLimit-* and X-Data-Version.

Where each piece is declared

// src/http/api.ts
HttpApi.make('naqwa')
  .add(companies, purification(coverage), meta)
  .middleware(RateLimit)      // only the groups added so far: everything under /v1
  .middleware(DataVersion)    // the last one added runs first
  .add(health)

// calculate, in the purification group
.middleware(RequestValidation).middleware(JsonBody)

// src/http/middleware.ts: the router's one global middleware
cors(app.pipe(
  catch RouteNotFound → 404, catchDefect → 500,
  map(setHeaders(SECURITY_HEADERS)),
))
Scoped by the API, not by the path. The rate limit and the data headers belong to the /v1 endpoints, so any spelling of a path that reaches one is counted, and nothing else is. An unknown /v1 path is answered by the router: 404, no quota used, no data headers. The order is explicit: an endpoint's middleware runs in the reverse of the order it was added (DataVersion, RateLimit, JsonBody, RequestValidation), and the router has a single middleware function. The contract test pins the result.

05Endpoint walkthroughs

What happens after the middleware hands the request to the router, endpoint by endpoint.

GET /v1/companies · src/http/handlers/companies.ts:15

  1. At boot, the handler group copies dataset.companies, sorts it by ticker, and maps each company to a summary: ticker, name, aliases, overallStatus(company), and availableYears (the years with a non-null rate, from publishedRates).
  2. It stores { count, companies } once.
  3. Per request, list: () => Effect.succeed(list). No work is done.
  4. The CompanyListSchema encodes it. The middleware adds Cache-Control: public, max-age=3600.

overallStatus (src/data/dataset.ts:76) collects the distinct non-null statuses across the company's years. It returns null if there are none, the single status if there is one, and "varies" otherwise. Tickers in unresolved are never listed.

GET /v1/companies/{ticker} · src/http/handlers/companies.ts:29

  1. The router matches /v1/companies/:ticker. TickerParams decodes the string to a positive integer. abc, 0 or -1 gets 400 with details[0].path = "ticker".
  2. resolveCompany(dataset, ticker) (src/http/errors.ts) calls dataset.lookup, which checks the companies map first, then the unresolved map:
    • found: returns the company
    • unresolved: yield* AmbiguousTicker.of(entry) → 409, with the candidate names in details.candidates
    • unknown: yield* UnknownTicker.of(ticker) → 404
  3. The handler maps every recorded year, sorted numerically, to { year, ratePerShare, status }. This includes years that have a status but a null rate, which is how the API reports, for example, that a company was non-pure in 2015 with no published rate.
  4. The response is cacheable for an hour.
{ "ticker": 2330, "name": "المتقدمة", "aliases": ["المتقدمة للبتروكيماويات"],
  "overallStatus": "varies",
  "years": [ { "year": 2015, "ratePerShare": null,   "status": "non-pure" },
             { "year": 2021, "ratePerShare": 0.026,  "status": "pure" }, … ] }

Sample from the contract test's small dataset (test/fixtures/contract.json).

GET /v1/companies/{ticker}/rates/{year} · src/http/handlers/companies.ts:46

  1. RateParams decodes ticker (a positive integer) and year (an integer). The year is not checked against the coverage here. A year outside it is a 404, not a 400.
  2. resolveCompany, as for the detail endpoint (404 / 409).
  3. publishedRate(company, year) (src/data/dataset.ts:61) returns null if the year is missing or its rate is null. A status alone cannot be used to calculate anything.
  4. null → yield* RateNotAvailable.of(...) → 404 RATE_NOT_AVAILABLE.
  5. Otherwise it returns { ticker, name, year, ratePerShare, status }.

POST /v1/purification/calculate · src/http/handlers/purification.ts

  1. Middleware: DataVersion and the rate limit, as on every /v1 endpoint, then JsonBody: the 100 KB cap, then Content-Type: application/json.
  2. Payload decoding with calculationRequestSchema(coverage) (src/http/schemas.ts:188): entries must have 1–100 items, and each entry is checked field by field (ticker a positive integer, shares finite and in (0, 1e12], and so on). All field errors are reported together.
  3. Rules across fields (src/http/schemas.ts:131) run per entry, and only the first broken rule is reported, in the order a person would fix them:
    • The entry must be in exactly one mode. Date mode uses purchaseDate with either saleDate or stillOwned. Days mode uses year with daysOwned.
    • Days mode: year must be within the coverage, and daysOwned ≤ (lastYear − year + 1) × 365.
    • Date mode: purchaseDate must be a real date (2023-02-30 is rejected) inside the coverage, saleDate is required unless stillOwned is set, saleDate cannot be after the coverage end, and the sale date must be after the purchase date.
  4. The handler runs Effect.forEach over the entries, in order, and it stops at the first failure. For each one:
    • resolveCompany(dataset, ticker, { entryIndex }). A failure stops the whole request with details.entryIndex.
    • toPeriod(entry, coverage) (purification.ts:13) builds a HoldingPeriod: {kind:'dates', start, end}, where end is the sale day or the coverage end day for stillOwned, or {kind:'days', startYear, days}.
    • calculateHolding(company, shares, period) splits the period into year segments and prices each one. If any year has no rate, it returns {ok:false, missingYear}, and the handler fails with 422 RATE_NOT_AVAILABLE.
  5. Totals. totalPurificationAmount is sumAmounts over every year row of every entry, not over the per-entry subtotals, because that is how the website sums. Each entry also has its own purificationAmount.
  6. Response: { currency: "SAR", totalPurificationAmount, entries: [{ index, ticker, companyName, shares, purificationAmount, years: [...] }] }. It is not cached.
All or nothing. A calculation never returns partial results. The first entry that fails decides the response, and details.entryIndex names it, so a client can point at the exact row.

GET /v1/meta and GET /health · src/http/handlers/meta.ts

  1. At boot, the group builds one object: apiVersion (from package.json), dataVersion (the SHA-256 prefix), coverage with its list of years, unit, formula, companyCount, the sorted unresolvedTickers, rateLimit.requestsPerMinute (the REQUESTS_PER_MINUTE config, so a test's limit shows here too) and maxEntriesPerRequest.
  2. /v1/meta returns that object. It is rate limited and cacheable.
  3. /health returns {"status":"ok"}. Its group is added to the API after the /v1 middleware, so it gets no rate limit and no data headers, and an uptime monitor can poll it freely. Render's healthCheckPath uses it.

GET /, /docs, /openapi.json · src/app.ts · src/http/api.ts

  1. / is a plain HttpRouter.add route that returns the API name, version and links.
  2. /openapi.json is generated by HttpApiBuilder.layer(api, { openapiPath }) from the same HttpApi value the handlers implement. Endpoint summaries, schema identifiers, examples, descriptions, and the errors each endpoint can return all come from api.ts, schemas.ts and errors.ts.
  3. /docs is Scalar's API reference from HttpApiScalar.layerCdn. The page embeds that document and loads Scalar from jsDelivr, at the version effect bundles (SCALAR_VERSION in app.ts).
  4. An endpoint documents the errors of the middleware it runs: 429 on every /v1 endpoint (RateLimit), 413 on calculate (JsonBody), and 400 only on the endpoints that take input (RequestValidation).

06The calculation

The domain layer (src/domain) has no Effect and no HTTP. It works in UTC day numbers, which are whole days since 1970-01-01. With no time of day and no time zone, daylight saving and the server's locale cannot change a day count.

Date mode

splitDateRangeIntoYears(start, end) (dates.ts:32) walks from start to the next 1 January, or to end if that comes first, and repeats. The end day is excluded: a full year runs from 1 January to the next 1 January, which is 365 or 366 days.

stillOwned uses the coverage end day (2024-12-31) as the excluded end, so 2024 counts 365 days.

Days mode

splitDaysIntoYears(startYear, days) (dates.ts:46) has no calendar. It cuts the count into consecutive 365-day blocks starting at startYear, and ignores leap days.

Validation caps daysOwned so the last block never goes past the coverage.

Pricing each year

// src/domain/purification.ts
roundAmount        = v => Number(v.toFixed(10))
purificationAmount = (shares, rate, days) => roundAmount((shares * rate * days) / 365)
sumAmounts         = amounts => roundAmount(amounts.reduce((t, a) => t + a, 0))

Each year is rounded to 10 decimal places, and each sum is rounded again, in the same order as the website's calculator. Changing the order (for example, summing unrounded values) would change the last digit, and the parity test would fail. The divisor is always 365, even for a 366-day leap year held in full.

How a typed error becomes a response

  1. Each business error is a Schema.Error class whose fields are the envelope ({ error: { code, message, details? } }), with httpApiStatus set on the class (src/http/errors.ts:24).
  2. A static of(...) builds the bilingual body, using errorBody(code, ar, en, details).
  3. Inside an Effect.gen or Effect.fn, return yield* UnknownTicker.of(t) fails the effect with that value. The error type is checked against the endpoint's declared error: [...] list.
  4. HttpApiBuilder encodes the error with its schema and uses its status. The endpoint can override the status, which is how calculate turns RateNotAvailable into a 422.
  5. The project rule: only middleware.ts builds an error response by hand. Those are the two cases the router answers itself, a route that does not exist and a defect, where no endpoint's error schema applies.

The rate limiter

  • A fixed window, not a sliding one. A client's first request opens a 60-second window, and the count resets when it expires (fixedWindow, rateLimit.ts).
  • Bounded memory. Windows are kept in the order they opened, and they all last a minute, so each request first drops the expired ones from the front of the Map. Past 10,000 clients, the oldest window is dropped to make room, so made-up addresses cannot run the process out of memory.
  • Client key. The first X-Forwarded-For entry if it is a real IP address (at most 45 characters, which rules out an IPv6 zone of any length), with the socket address as the fallback, which is also the key in local runs. Whether Render's proxy lets a client choose that entry is unverified (the README's Deployment section has a check), so the limit is a courtesy, not a security boundary.
  • One process only. Counters live in memory, so they are correct only for a single instance and reset on every restart.

Validation at load

decodeDataset (src/data/schema.ts) decodes the file once, with errors: 'all' and onExcessProperty: 'error':

  • Fields. Tickers are integers from 1000 to 9999. Names are trimmed and non-empty. A rate is finite and ≥ 0, or null. A status is one of pure, mixed, non-pure or public-sector, or null. A year with neither a rate nor a status is an error, because it should be left out.
  • Rules across records (crossRecordIssues, a check on DatasetSchema). coverage.start < end, no ticker appears twice across companies and unresolved, and every year key is inside the coverage. Effect runs them once every field is valid, so a broken field is reported first and these on the next run.

If there are any problems, it throws one Error that lists them as path: message.

Concepts worth knowing

  • Classification is per year. There is no company-wide category. overallStatus is derived from the years.
  • Published means it has a rate. A year with only a status shows up in the company detail, but cannot be priced.
  • public-sector is the site's former Aramco category: a state-owned company treated as permissible.
  • unresolved keeps every candidate verbatim for a ticker the source assigns to two companies. Lookups return 409 until the owner decides. Never fill one in by guessing. The real data currently has none, so the tests add a fake ticker, 9998.
  • Canonical layout (src/data/format.ts): sorted by ticker, years sorted, one year per line, so a rate change is a one-line diff. A test fails if the file drifts from this layout.

10Tests

pnpm check runs typecheck, lint and test, which is what CI runs. All HTTP tests go through makeTestApp, so they run the real middleware and handlers in memory.

api.test.ts

Behaviour by endpoint: listing, detail, rates, calculation in both modes, validation messages, size limits, the 404/409/422 paths with entryIndex, meta, rate limiting with a fake clock (that /health is not counted, and that every spelling of a path reaching an endpoint is), and CORS.

contract.test.ts

Pins the status, every header, and the body for about 35 requests covering every endpoint and every error code, in fixtures/contract.json. It runs on its own two-company dataset, so editing the real data does not affect it. To re-record after an intended change: UPDATE_CONTRACT=1 pnpm test.

parity.test.ts

Compares the API with outputs recorded from the website's own calculator (fixtures/legacy-site.json): every company × year rate, and about 1,700 generated holdings in both modes, to the last decimal. No build step and no bundler. Relative imports end in .ts, type imports use import type, and there are no enums or parameter properties.Node strips types at runtime. erasableSyntaxOnly and the linter enforce this.
